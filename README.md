# 五子棋 · Gomoku

一个功能完整的五子棋网页游戏：**人机对战（一至九段 AI）**、**本地双人**、**局域网联机**、**互联网联机**，
支持悔棋、认输、重新开局、观战、实时聊天、断线重连、对局历史（含回放）、落子音效与对局计时。

**零后端**：联机采用 WebRTC 点对点直连（PeerJS），数据不经过任何中转服务器；
信令服务仅用于建立连接，默认使用 PeerJS 官方公共信令，可配置为自托管。

---

## 快速开始

### 方式一：双击打开（最简）

直接双击 `index.html` 即可运行。人机对战与本地双人立即可用；联机模式需要能访问公网信令 CDN
（页面已做 jsdelivr + unpkg 双 CDN 兜底）。

### 方式二：本地静态服务器（推荐，局域网设备互连必需）

```bash
# 在项目目录下执行其一：
python -m http.server 8000
# 或
npx serve .
```

浏览器访问 `http://localhost:8000`。同一局域网内的其他设备访问
`http://<本机IP>:8000` 即可加载同一页面（联机数据走 P2P 直连）。

## 四种模式怎么玩

### 1. 人机对战
首页进入「人机对战」→ 对局界面开局设置区选择段位（1-9 段）与先手/禁手/三手交换 → 点「开始对局」。
AI 按段位调整搜索深度与失误率。

### 2. 本地双人
一台设备上双人轮流落子（黑先白后），适合平板/手机与朋友同屏对弈。开局设置区可选黑棋禁手/三手交换。

### 3. 局域网联机
- 一方点「局域网联机 → 创建房间」，获得 4 位房间码
- 对方点「加入房间」输入房间码即可对局（可跨设备、跨浏览器）
- 数据在局域网内 P2P 直连，不经过公网

### 4. 互联网联机
同样通过房间码互连，但双方处于不同网络（NAT 后）时，由 PeerJS 公共信令协助
完成 NAT 穿透（STUN/TURN）。**注意**：无服务器架构没有"中央匹配池"，
"在线匹配"即分享房间码——把房间码发给对方即可跨网络对战。

## 断线重连 / 观战 / 聊天

- **断线重连**：任一玩家掉线后，席位保留 90 秒；重进同一房间码即可自动恢复棋局
  （host 下发完整状态快照）。超时未归判负。
- **观战**：房间玩家位满（2 人）后，第 3 个及以后的连接自动成为观战者，只读观看。
- **聊天**：侧栏聊天框实时收发，房间内全员可见。

## 自托管信令（可选，解决公共信令不可达/延迟）

默认公共信令在部分网络环境可能不可达。可自建信令服务器（约 1 分钟）：

```bash
npm install -g peer      # 需要 Node.js 环境
peer --port 9000          # 在服务器（或局域网某台机器）上运行
```

然后修改 `index.html` 顶部的 `PEER_CONFIG`：

```js
window.PEER_CONFIG = {
  host: '192.168.1.100',  // 信令服务器地址（局域网 IP 或公网域名）
  port: 9000,
  path: '/',
  secure: false,          // 公网 HTTPS 场景改为 true
  debug: 0
};
```

**提示**：局域网联机时，若公共信令不可达，双方都改成上述自托管地址即可；
公网部署时请将信令服务器放在有公网 IP 的机器上（或用 frp 内网穿透映射）。

## 部署到公网（互联网联机）

静态页面可部署到任意静态托管（GitHub Pages / CloudStudio / Nginx 等），
联机数据仍是 P2P，无需后端：

```bash
# 以 GitHub Pages 为例
git init && git add . && git commit -m "gomoku"
git remote add origin <你的仓库地址>
git push -u origin main
# 仓库 Settings → Pages → 选择 main 分支 → 生效
```

若目标用户在国内网络，建议同时自托管信令并修改 `PEER_CONFIG`。

```
gomoku/
├── index.html          入口：视图骨架 + PeerJS 双 CDN + PEER_CONFIG
├── css/style.css       墨色极简主题，响应式（桌面 / 移动端）
├── js/
│   ├── engine.js       核心规则引擎：15×15 棋盘、胜负判定、悔棋（纯逻辑）
│   ├── ai.js           九段 AI：评分表 + α-β 剪枝 + 迭代加深 + 随机扰动

│   ├── storage.js      对局历史（localStorage，上限 50 局）
│   └── app.js          UI 总控：视图路由、Canvas 渲染、计时、聊天、回放
└── DESIGN.md           设计文档（架构 / 协议 / 取舍）
```

## 架构与协议要点

| 项目 | 说明 |
|---|---|
| 联机拓扑 | host（房主）为权威节点：校验并广播所有落子；client 与观战者只响应广播 |
| 房间标识 | 房间码 4 位（去易混淆字符），Peer ID = `gomoku-<房间码>` |
| 消息协议 | `hello / welcome / move / chat / undo-req/ok/no / undo-done / resign / restart-* / player-list / state-sync / ping/pong`（DataChannel JSON） |
| 一致性 | host 权威 + 广播回显；任何端不本地直接落子（联机），杜绝双端分歧 |
| 重连 | client 断线自动指数退避重连（2s→16s 封顶），带原身份恢复席位 |
| 计时 | host 权威计时，随广播同步；观战者只读 |
| 历史 | localStorage 存储，含完整走子序列，可步进回放 |

## 已知限制

- 互联网联机为「房间码分享」模式，无中央匹配池（无服务器架构的固有形态）；
  如需自动匹配需引入后端，`net.js` 协议层已做隔离，可替换为 WebSocket 实现。
- 联机悔棋 / 重开需对方同意；断线重连有 90 秒席位保留窗口。
- 对局记录仅保存在本机浏览器（无服务器存储）。
